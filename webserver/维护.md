# 维护说明

沙箱上跑着一个需要登录的远程浏览器。手机 App 或电脑浏览器先向云服务器要当前入口，再直接连沙箱上的 Cloudflare 隧道。网页、画面和声音不经过云服务器。

云服务器的公网地址、端口、上报令牌和加密口令都在沙箱的 `webserver/data/vps.conf`，不写入本文，也不提交到 Git。登录用户名和密码在 `webserver/data/auth.json`。

## 各台机器做什么

| 位置 | 作用 |
| --- | --- |
| 沙箱 | 提供登录页和远程 Chrome。用 Cloudflare Quick Tunnel 得到一个会变化的 `https://….trycloudflare.com`。 |
| 云服务器 | 只保存并交出沙箱报上来的内容。程序是 `gate-addr`。 |
| 手机 App | 向云服务器读取内容，在手机上解开，再打开沙箱网页。 |

直接打开云服务器网站根路径会得到 `403 Forbidden`，正文只有这一行。`/address` 返回 `g1.` 开头的一串字符。加密口令不要放到云服务器上。

## 沙箱上的程序

监管进程是 `webserver/boot.sh`。它没有 systemd 时会一直循环，负责：

- 本机 `http://127.0.0.1:8080/login` 打不开时，拉起 `server.py`
- 没有 `cloudflared` 时，拉起 `run-tunnel.sh`
- 隧道已经运行、但域名变成 NXDOMAIN 时，换一条新隧道
- 把当前地址写成 `webserver/data/public-url.txt`

`run-tunnel.sh` 在沙箱上把地址加密，然后：

```bash
curl -4 -X POST http://<VPS_IP>:<VPS_PORT>/address \
  -H "X-Gate-Token: <ADDR_TOKEN>" \
  -H "Content-Type: text/plain" \
  --data-binary "<g1.密文>"
```

云服务器返回 `204` 表示已经保存。若仍是旧程序并返回 `400`，沙箱会再提交一次明文地址，日志里会出现 `cloud server rejected ciphertext and stored the plain address`。新程序安装好以后，这条补发不再发生。

一键重启只重开网页和远程浏览器。隧道地址还能打开就保持不变；打不开就更换。令牌从 `vps.conf` 读取，不用再填。

```bash
bash /workspace/webserver/restart.sh
```

日志：

- `webserver/data/web.log`
- `webserver/data/cloudflared.log`

## 怎样确认现在可用

在沙箱上执行：

```bash
curl -s -o /dev/null -w 'local:%{http_code}\n' --max-time 5 http://127.0.0.1:8080/login
```

`local:200` 表示本机网页在服务。再看 `webserver/data/public-url.txt` 里的地址，请求它的 `/login` 也应是 `200`。

然后看云服务器的 `/address`。用 `vps.conf` 里的地址和 `ADDR_KEY` 解密，结果应与 `public-url.txt` 相同。机器是 x86_64 时用 amd64 程序，aarch64 时改成 arm64：

```bash
cd /workspace/webserver
set -a
. ./data/vps.conf
set +a
url=$(tr -d '[:space:]' < data/public-url.txt)
blob=$(curl -4 -fsS --max-time 10 "http://${VPS_IP}:${VPS_PORT}/address" | tr -d '[:space:]')
./vps/offline/gate-seal-linux-amd64 decrypt "$ADDR_KEY" "$blob"
printf '%s\n' "$url"
```

两行输出一致才算云服务器上的内容是当前隧道。端口是 80 时，curl 地址不要加 `:80`。

云服务器网站根路径应是 `403 Forbidden`，不要出现跳转到 `trycloudflare.com` 的页面。

## 沙箱重启之后

进程不会自己留下来。新的沙箱要在开机时执行：

```bash
bash /workspace/webserver/boot.sh
```

这条命令会一直运行，所以应放在 Cursor 环境的 `start` 里，而不是 `install` 里。当前这个环境的配置在控制台，不在仓库文件里：

https://cursor.com/dashboard/cloud-agents/environments/e/7671edb3-c462-11f1-ac31-5e2d0494121f

只改 `start` 还不够。`webserver/data/` 不进 Git，`cloudflared` 和 Chrome 也是后来装上的。新沙箱若从旧磁盘快照启动，会缺少口令或程序。需要把已经配好的这台机器做成新快照，之后的沙箱才带得上这些文件。

重启后 Quick Tunnel 的名字会变。旧的 `trycloudflare.com` 地址作废。云服务器上的固定入口不用改，App 重新填写入口后再读 `/address`。

## 云服务器

安装目录是上传上去的 `webserver/vps/offline/`。已经装过时，在该目录再执行一次：

```bash
sudo bash setup-addr.sh
```

脚本会保留 `/etc/gate-addr/token` 和现有对外端口，替换 `/usr/local/bin/gate-addr` 并重启 `gate-addr`。若以前手动加过 `gate-addr-front`，这次会停掉它。

更新后在云服务器上检查：

```bash
systemctl status gate-addr --no-pager
curl -sI http://127.0.0.1:8080/ | head -n 1
curl -s http://127.0.0.1:8080/
curl -s http://127.0.0.1:8080/address
```

第一行是 `HTTP/1.1 403 Forbidden`，正文只有 `403 Forbidden`。`/address` 是 `g1.` 开头。curl 里的端口要与 `gate-addr.service` 的 `-listen` 一致，也要与沙箱 `vps.conf` 的 `VPS_PORT` 一致。

早期的流量转发是 `frps`，服务名 `gate-frps`，控制端口 `7000`。现在不要再用它转网页。卸载：

```bash
sudo systemctl disable --now gate-frps.service
sudo pkill -f '/usr/local/bin/frps' || true
sudo rm -f /etc/systemd/system/gate-frps.service /usr/local/bin/frps /var/log/gate-frps.log
sudo rm -rf /etc/gate-frp
sudo systemctl daemon-reload
```

不要删除 `/usr/local/bin/gate-addr`、`/etc/gate-addr/`、`/var/lib/gate-addr/` 和 `gate-addr.service`。

任何知道 `ADDR_TOKEN` 的机器都可以向 `/address` 提交新内容并覆盖旧值。令牌只留在沙箱的 `vps.conf` 和云服务器的 `/etc/gate-addr/token`。

## App

包名 `app.sandbox.gate`。发布包文件名是 `webserver/android/Gate-<versionName>.apk`。当前版本是 `Gate-1.8.apk`（versionName `1.8`）。

登录页不预置云服务器地址，需要使用者自己填写一次。填过的入口只保存在这台手机上。App 读取 `<入口>/address`，用内置口令解开，再打开沙箱网页。保存的隧道地址打不开时，用该入口再取一次新地址。新地址需要重新登录。安装包里没有云服务器地址。

重新打包：

```bash
cd /workspace/webserver/android
export ANDROID_HOME=/opt/android-sdk ANDROID_SDK_ROOT=/opt/android-sdk
./gradlew assembleRelease --offline
```

改版本时同时改 `app/build.gradle` 的 `versionName` 和 `versionCode`。打包结果会写成 `webserver/android/Gate-<versionName>.apk`。签名信息在不提交的 `keystore.properties`。

## 常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `restart.sh` 一直打印仍在等待隧道地址 | 旧隧道进程还在，但 Cloudflare 名字已经删除 | 使用当前的 `restart.sh`。它会停掉失效隧道并等待新地址的 `/login`。 |
| App 打开后一直进不去 | 手机还记着已经删除的隧道名字，或 1.7 把入口清掉后地址栏是空的 | 安装 `Gate-1.8.apk`，完全退出旧 App，在入口地址里重新填写一次。之后隧道换名会自己重新读取入口。 |
| 云服务器根路径出现 `302` 和明文网址 | 云服务器仍是旧程序 | 重新上传 `webserver/vps/offline/`，执行 `sudo bash setup-addr.sh`。 |
| 沙箱日志不断出现明文补发 | 云服务器拒绝了 `g1.` 内容 | 同上，换成新程序后补发会停止。 |
| 新沙箱开机后没有网页 | `start` 没有运行 `boot.sh`，或快照里没有 `data/` 和已安装程序 | 按上面的开机和快照说明处理。 |

画面慢、页面忽大忽小、输入迟缓，来自当前的截图传输：手机每次拉取一张完整 JPEG，点击和文字再各走一次跨国请求。这不是云服务器转发流量。后续若要改善手感，优先保持画面比例、避免拉伸，并缩短观看路径；不要把网页流量改回云服务器中转。
